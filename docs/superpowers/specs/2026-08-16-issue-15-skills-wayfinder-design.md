# Issue #15 Skills and Wayfinder Integration Design

## Goal

Provide a stable Phase 2 CLI contract that Codex, Claude Code, and wayfinder can consume without guessing command availability, while keeping wayfinder itself outside this repository.

## Scope and order

Issue #15 owns the integration, packaging, examples, and forward tests. The CLI capabilities it consumes are implemented in the same worktree in this order:

1. Schema migration foundation already present on `main`.
2. Issue `blocks` dependencies and the one-level parent relation.
3. Atomic claim, session lease, heartbeat, stale display, and reasoned takeover.
4. Multiple human decision requests and resolution.
5. Event cursor and capability discovery.
6. Codex and Claude Code skills, wayfinder examples, compatibility fixtures, and forward tests.

Idempotency remains an optional capability owned by its separate roadmap work. Skills use it only when capability discovery reports it.

## Data model

Schema version 3 adds:

- `issue_dependencies` for directed `blocks` relations. A blocker cannot equal its blocked Issue, duplicate edges are rejected, and transitive cycles are rejected.
- `issue_parents` for a single parent per child. Nested parent chains are rejected so the relation remains one level deep.
- `issue_leases` for one active lease per Issue, keyed by agent and session ID, with a 15-minute expiry and heartbeat timestamp.
- `decision_requests` for multiple open or resolved requests per Issue, including question, background, requester context, answer, resolver context, and resolution timestamp.

Issue assignment remains agent-level. Lease ownership is the `agent + session_id` pair. Claim and takeover update assignment, state, lease, revision, and audit/domain events atomically. Heartbeat only updates lease timing and does not increment Issue revision or emit a cursor event.

## CLI contract

The Phase 2 command names are:

```text
bettr issue dependency add BLOCKER BLOCKED
bettr issue dependency remove BLOCKER BLOCKED
bettr issue dependency list NUMBER
bettr issue parent set CHILD PARENT
bettr issue parent list NUMBER
bettr issue claim [NUMBER]
bettr issue heartbeat NUMBER
bettr issue takeover NUMBER --reason REASON
bettr decision request NUMBER --question QUESTION --background BACKGROUND
bettr decision resolve REQUEST_ID --answer ANSWER --next-state STATE
bettr event list --after CURSOR [--limit LIMIT] [--include-issue]
bettr capabilities --json
```

Relation arguments use `PROJECT#NUMBER`; an unqualified number uses the global `--project` context. `claim` without a number selects the highest-priority eligible `todo` Issue by priority and creation time. It excludes Issues with unresolved blocking dependencies or open human decision requests. Claim uses the current agent and session execution context; `BETTR_AGENT` is required for agent claim operations and `BETTR_SESSION_ID` is generated by the caller when absent.

Lease defaults are fixed at 15 minutes. Heartbeat extends the same lease and is valid only for the current owner. An expired lease is displayed as stale but never changes Issue state automatically. Takeover requires a nonblank reason and changes the owner in one transaction.

Creating a decision request moves the Issue to `blocked` with human wait metadata in the same transaction. Resolving a request records the answer and human context and applies an explicit next state. An Issue with any unresolved request cannot transition to `done`; the resolver cannot be the requesting agent session.

Event cursors are exclusive integer sequences over successful committed data changes. Reads, failures, and heartbeat renewals are omitted. The response returns `next_cursor`, `has_more`, and safe event objects containing event type, target IDs, changed fields, revision, timestamp, and optional post-change Issue data. A single read transaction supplies the snapshot.

`capabilities --json` returns the JSON contract version, CLI version, and capability names. Consumers fail closed for unsupported contract versions and unknown capabilities, ignore additive fields, and never infer commands from their names.

## Skill packaging

The existing Codex skill remains under `skills/bettr`. The Claude Code adapter is added under `skills/bettr-claude`. Both reference the machine-readable capability matrix at `contracts/capabilities.json`; runtime-specific installation and invocation instructions remain in each skill package.

The skill workflow is capability discovery, execution context setup, claim, bounded heartbeat, decision request and stop when blocked, verified completion, and revision-aware conflict handling. The repository provides examples and contract fixtures for wayfinder but does not embed wayfinder code, add a daemon, or add authentication.

## Verification

Rust integration tests cover migration rollback, dependency cycle prevention, claim races, lease ownership and expiry, decision resolution constraints, cursor pagination and snapshot behavior, capability output, and unsupported command/version handling. Skill tests verify that both runtime packages mention only capabilities declared by the shared matrix and that the end-to-end fixture covers claim, decision, event polling, and completion.
